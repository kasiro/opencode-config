Self-improving AI Agents

Исследование механизмов самоулучшения AI-агентов: от lesson-loop до multi-agent эволюции. Дата: июль 2026.

1. Lesson Loop Pattern

Цикл самоулучшения: фундаментальный паттерн, при котором агент выполняет задачу, фиксирует неудачу/ошибку, извлекает урок, сохраняет его в долговременную память и применяет в будущем.

execute → fail → extract_lesson → store → retrieve → apply → improve

Ключевые элементы успешного Lesson Loop:

  • Верификация урока: урок должен быть проверен на релевантность перед сохранением (confidence score)
  • Контекстная привязка: урок хранится вместе с контекстом (проект, тип задачи, файл)
  • Автоматическое применение: при старте похожей задачи уроки автоматически загружаются
  • Decay-механизм: неиспользуемые уроки со временем теряют вес

В OpenCode этот паттерн реализован через agentmemory_memory_lesson_save и agentmemory_memory_lesson_recall. Confidence score обновляется при каждом успешном использовании урока.

2. HyperAgents (Meta, 03.2026)

HyperAgents — фреймворк Meta Research для cross-domain transfer улучшений между агентами. Ключевая инновация: улучшения, полученные одним агентом в одной предметной области, автоматически передаются другим агентам в других областях.

Архитектура

  • Agent Pool: популяция агентов с разными специализациями
  • Evolve Controller: анализирует успешные стратегии и мутирует их в другие домены
  • Cross-domain Mapper: отображает уроки из одной предметной области в другую
  • Fitness Function: метрика успеха для каждого агента

Multi-Agent Evolve

Процесс эволюции:

  1. Агенты выполняют задачи и записывают траектории (prompt → action → result)
  2. Evolve Controller выбирает лучшие траектории (top-k по fitness)
  3. Мутация: лучшие траектории комбинируются и адаптируются для других доменов
  4. Новые траектории загружаются в промпты агентов
  5. Цикл повторяется каждые N итераций

Результаты Meta: улучшение accuracy на 23-47% в cross-domain сценариях по сравнению с изолированным обучением.

3. SAGE: 4-агентная архитектура

SAGE (Self-improving AGent with Evolution) — архитектура с четырьмя специализированными агентами и защитой от дрейфа curriculum.

АгентРольФункция
ChallengerГенерация задачСоздаёт задачи возрастающей сложности для Solver-агента
PlannerСтратегияРазрабатывает план решения, разбивает на подшаги
SolverИсполнениеВыполняет шаги плана, генерирует код/действия
CriticОценкаАнализирует результат, извлекает уроки, обновляет память

Curriculum Drift Prevention

Критическая проблема self-improving систем: агент может «застрять» на лёгких задачах, избегая сложных. SAGE решает это через:

  • Автоматическое повышение сложности: Challenger анализирует историю успехов и повышает сложность на 10-20% при N последовательных успехах
  • Struggle Detection: если Solver не может решить задачу после K попыток, Challenger понижает сложность на 30%
  • Diversity Reward: агент получает бонус за использование новых стратегий (не повторение старых)

4. SWE-RL: RL на результатах кода

SWE-RL (Software Engineering Reinforcement Learning) — техника, при которой агент обучается через reinforcement learning на реальных результатах выполнения кода (unit test pass/fail, compilation success, code review score).

Как работает:

  1. Агент генерирует код для задачи
  2. Код выполняется в изолированной среде (sandbox)
  3. Результат: pass/fail тестов, ошибки компиляции, coverage
  4. RL-алгоритм (PPO/GRPO) обновляет веса LM через reward signal
  5. Цикл повторяется тысячи раз

Результаты: SWE-RL на базе Qwen2.5-Coder-7B достиг 41.6% solve rate на SWE-Bench Verified, превзойдя GPT-4o (33.2%) при значительно меньшем размере модели.

Ключевые компоненты успеха:

  • Высококачественный reward signal (не binary pass/fail, а graded: compilation → tests → style → perf)
  • Разнообразие задач (не переобучаться на одном типе)
  • Правильный balance между exploration и exploitation

5. Prompt Optimization Loop

Методология A/B тестирования промптов для автоматического улучшения качества ответов агента.

Цикл оптимизации:

  1. Baseline: текущий промпт выполняет задачу N раз
  2. Variant: изменённый промпт (добавление/удаление инструкций, изменение порядка)
  3. A/B Test: оба варианта выполняют одинаковые задачи, результаты сравниваются
  4. Winner Selection: вариант с лучшей метрикой становится новым baseline
  5. Mutation: новый baseline мутирует (изменение 10-30% контента) для следующего раунда

Метрики для сравнения:

  • Accuracy: правильность ответа (0-1)
  • Completeness: полнота охвата требований
  • Token Efficiency: количество токенов на единицу результата
  • User Satisfaction: оценка пользователя (thumbs up/down)

Для OpenCode может быть реализовано через плагин, который перехватывает запросы, применяет разные версии system prompt и логирует результаты.

6. METR: темп улучшения агентов

METR (Model Evaluation and Threat Research) — организация, отслеживающая прогресс AI-агентов. Ключевое наблюдение: сложность задач, которые могут решать агенты, удваивается каждые 7 месяцев.

ГодПример задачиОценка сложности (METR)
2023Написание простых функций, вопросы-ответы по документации1.0
2024Многошаговый рефакторинг, деплой простых приложений3.5
2025End-to-end разработка модулей, дебаг production инцидентов8.2
2026Cross-repo рефакторинг, архитектурные решения, автономные исследования16.0+

Импликация: self-improving механизмы критичны — без них агент будет отставать от exponentially улучшающихся конкурентов.

8. Рекомендации

  1. Верификатор уроков: добавить агента-верификатора, который проверяет качество урока перед сохранением (relevance, specificity, actionability). Confidence < 0.3 — rejected, 0.3-0.7 — requires review, > 0.7 — auto-save.
  2. Multi-Agent Evolve: имплементировать HyperAgents-style pool, где агенты обмениваются успешными стратегиями через agentmemory signals. Оркестратор выбирает top-k траекторий каждые 100 задач.
  3. Meta-learning layer: добавить слой, который анализирует паттерны в saved lessons и синтезирует higher-order правила (обобщения из частных уроков).
  4. Curriculum Manager: Challenger-агент, автоматически подбирающий задачи для прокачки слабых мест Solver-агентов.
  5. SWE-RL integration: для code generation задач добавить RL fine-tuning через sandbox execution результатов.
