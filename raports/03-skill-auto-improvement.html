🔍 Механизм авто-загрузки скиллов

OpenCode автоматически обнаруживает и загружает скиллы при старте сессии. Механизм работает через frontmatter в SKILL.md — YAML-блок в начале файла, содержащий name и description.

---
name: agent-delegation
description: |-
  Agent delegation system for J.A.R.V.I.S. — who does what. executor (code, edits, git),
  researcher (web research, deepwiki, exa), sysadmin (system diagnostics, monitoring),
  general (multistep code+research hybrid), explore (fast read-only navigation).
  Use proactively when a task matches an agent's specialization.
---

Принцип работы:

  1. При старте сессии OpenCode сканирует директории скиллов
  2. Читает name и description из frontmatter каждого SKILL.md
  3. Помещает описание в system prompt как <available_skills>
  4. Агент в CYCLE 1 → ORIENT проверяет: если задача подходит под описание скилла — вызывает skill(name="...")
  5. Skill-инструмент инжектит полный SKILL.md в контекст

📁 Структура скилла

skill-name/
├── SKILL.md          # Главный файл (frontmatter + инструкции)
├── scripts/          # Исполняемые скрипты (Python, Bash, JS)
│   ├── deploy.sh
│   └── analyze.py
├── references/       # Документация, шпаргалки, примеры
│   └── api-reference.md
└── assets/           # Изображения, шаблоны, конфиги
      └── template.json

📊 Progressive Disclosure (3 уровня)

Описание скилла раскрывается постепенно, чтобы не тратить контекст:

УровеньЧто видит агентКогда
1. System prompt Только name + description из frontmatter Всегда в prompt
2. Skill content Полный SKILL.md + пути к scripts/references/assets После вызова skill(name="...")
3. Scripts/References Содержимое файлов из scripts/, references/ Когда агент явно читает файл

✍️ Правила описания скиллов

  • Action verb: начни с глагола действия ("Use...", "Evaluate...", "Search...", "Create...")
  • Не "You are": избегай "You are a..." — это тратит контекст, не добавляет ценности
  • |- literal block scalar: используй |- для многострочного описания (YAML)
  • Примеры: обязательно добавь секцию Examples с конкретными use cases
  • STRONG TRIGGERS: если скилл должен срабатывать на определённые фразы — укажи их
  • Do NOT trigger: укажи когда скилл НЕ должен вызываться (чтобы избежать ложных срабатываний)

🛠️ Skill-creator процесс

  1. Understand — понять задачу: какой пробел закрывает скилл
  2. Plan — структура: нужен ли scripts/ или достаточно SKILL.md
  3. Initialize — создать директорию и SKILL.md с frontmatter
  4. Edit — написать инструкции, примеры, скрипты
  5. Validate — проверить что frontmatter корректен, description информативен
  6. Iterate — улучшать на основе реального использования

Авто-коммит: при изменениях скиллов (создание/обновление SKILL.md) автоматически создаётся git commit с сообщением skill: update [name].

💡 Рекомендации по улучшению

  • Добавить STRONG TRIGGERS во все скиллы — это улучшает авто-детекцию
  • Добавить Do NOT trigger везде, чтобы избежать ложных срабатываний
  • Укоротить описания — в system prompt попадает весь description, он должен быть лаконичным
  • Action verb в начале — "Use...", "Search...", "Evaluate..." — помогает агенту быстро понять назначение
  • Примеры в description — добавляют контекст и ускоряют понимание
  • Обновлять metadata — скиллы эволюционируют, описание должно отражать текущие возможности
