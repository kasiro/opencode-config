Варианты интеграции STT в OpenCode

A. Whisper MCP сервер Рекомендуется

Плюсы: Лучшее качество распознавания (OpenAI Whisper Large-v3). Поддержка 99+ языков. Работает через MCP — нативно для OpenCode.

Минусы: Требует GPU для реального времени. Без GPU — задержка 5-15 сек на CPU. Модель ~3 ГБ.

Схема работы:

# MCP сервер whisper
# opencode.json → mcpServers.whisper
# Инструменты:
# - transcribe(audio_data: base64) → text
# - transcribe_file(path: str) → text

# Псевдо-конфиг:
{
  "mcpServers": {
    "whisper": {
      "command": "python3",
      "args": ["/home/kasiro/.config/opencode/mcp/whisper_server.py"],
      "env": {
        "WHISPER_MODEL": "large-v3",
        "WHISPER_DEVICE": "cuda"  # или cpu
      }
    }
  }
}

B. Vosk MCP сервер

Плюсы: Быстро (реальное время даже на CPU). Офлайн. Лёгкий (~50 МБ модель). Простая интеграция через MCP.

Минусы: Качество хуже Whisper (особенно шум, акценты, специфическая лексика). Модели ограничены по языкам.

Использование: Для базовых команд (включить/выключить, открыть приложение) — достаточно. Для сложных диалогов — нет.

C. Whisper.cpp

Плюсы: Работает на CPU с хорошей скоростью. Оптимизирован (GGML/GGUF, квантование). Можно запустить как подпроцесс или MCP.

Минусы: Требует компиляции C++ кода. Интеграция сложнее, чем чистый Python.

Компромисс: Лучший вариант для CPU-only систем. Качество между Vosk и Whisper full.

D. Плагин OpenCode + внешняя программа

OpenCode плагин на TypeScript, который вызывает внешнюю STT программу через subprocess (например, whisper-cli или vosk-cli).

Плюсы: Гибкость. Можно переключать бэкенд.

Минусы: Дополнительный слой абстракции. Не использует нативный MCP протокол.

Пошаговый план внедрения

День 1 — Микрофонный плагин

  • Создать MCP сервер microphone для захвата аудио с микрофона
  • Инструменты: start_listening(), stop_listening(), get_audio_chunk()
  • Использовать sounddevice для PortAudio
  • Тест: захват 5 секунд и сохранение в WAV

День 2 — STT ядро

  • Выбрать бэкенд: Whisper MCP (если GPU) или Vosk MCP (если CPU)
  • Создать MCP сервер stt с инструментом transcribe(audio: base64) → text
  • Интегрировать VAD (Silero VAD через silero-vad pip пакет)
  • Тест: WAV → STT → текст

День 3 — Wake Word

  • Выбрать: RustPotter (лёгкий) или Porcupine (Picovoice, точный)
  • Создать MCP сервер wakeword с инструментом detect(audio: base64) → bool
  • Настроить ключевое слово: "OpenCode" или "Jarvis"
  • Тест: пайплайн микрофон → VAD → WakeWord → логирование

День 4 — TTS и аудио-выход

  • Интегрировать opencode-voice-plugin как MCP сервер TTS
  • Инструменты: say(text: str) → void (воспроизвести), save(text: str, path: str) → file
  • Добавить звуки: начало прослушивания (beep), конец (double-beep), ошибка
  • Тест: полный цикл "Скажи привет" → TTS → динамики

День 5 — Интеграция и тестирование

  • Соединить все MCP сервера в OpenCode конфиг
  • Создать голосовой loop: Listen → VAD → WakeWord → STT → OpenCode → TTS
  • Тест: "Jarvis, открой браузер" → полный цикл
  • Оптимизация: пороги VAD, таймауты, буферизация

Итоговая архитектура MCP серверов

opencode.json — добавление в mcpServers:

{
  "mcpServers": {
    "microphone": {                // День 1: захват аудио
      "command": "python3",
      "args": ["mcp/microphone_server.py"]
    },
    "vad": {                        // День 2: детекция голоса
      "command": "python3",
      "args": ["mcp/vad_server.py"]
    },
    "wakeword": {                   // День 3: "Jarvis" / "OpenCode"
      "command": "python3",
      "args": ["mcp/wakeword_server.py"]
    },
    "stt": {                        // День 2: Whisper или Vosk
      "command": "python3",
      "args": ["mcp/whisper_server.py"]
    },
    "tts": {                        // День 4: озвучка ответа
      "command": "npx",
      "args": ["@modelcontextprotocol/server-tts"]
    }
  }
}

Резюме: OpenCode сегодня — "немой" инструмент. Голос — самое слабое место. Но MCP архитектура позволяет добавить голос как набор серверов без изменения ядра. 5 дней на базовую интеграцию.
