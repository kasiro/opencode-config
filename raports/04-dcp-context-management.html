🔍 Что такое DCP

Dynamic Compression Protocol (DCP) — плагин для OpenCode, реализующий динамическое управление контекстным окном. Установлен через @tarquinen/opencode-dcp@3.1.13. Основная задача: автоматически сжимать старый контекст, когда окно приближается к лимиту модели.

Плагин зарегистрирован в ~/.opencode/opencode.json в секции plugin.

{
  "plugin": [
    "@prevalentware/opencode-goal-plugin",
    "opencode-intellisearch",
    "@tarquinen/opencode-dcp@3.1.13"
  ]
}

🔄 Режимы сжатия

mode "range" — Диапазонное сжатие

Текущий режим. Сжимает диапазон сообщений между protected зоной и началом контекста. Включает суммаризацию (summaryBuffer) для сохранения смысла.

mode "summary" — Суммаризация

Заменяет старые сообщения их кратким содержанием. Более агрессивное сжатие, но теряет детали.

mode "drop" — Удаление

Просто удаляет старые сообщения. Самое агрессивное, но теряет контекст полностью.

🛡️ Стратегии сжатия

Deduplication (включена)

Удаляет дублирующийся контент между сообщениями. Полезно при повторяющихся вызовах инструментов с одинаковыми результатами.

protectedTools: список инструментов, вывод которых не подлежит дедупликации (на данный момент пуст).

PurgeErrors (включена, turns: 6)

Удаляет старые сообщения об ошибках и выводы инструментов через 6 шагов. Очищает контекст от шума, но сохраняет недавние ошибки для дебага.

🤝 Взаимодействие DCP и OpenCode compaction

В opencode.json есть встроенная секция compaction:

"compaction": {
    "auto": false,
    "prune": false
  }
МеханизмСтатусОписание
DCP (плагин)ВключёнДинамическое сжатие по проценту контекста
OpenCode compactionВыключенВстроенное сжатие (хвостовые сообщения)

Рекомендация: Используй ОДИН основной механизм. DCP активен — compaction OpenCode отключён (auto: false, prune: false). Если оба активны — DCP может сжимать то, что compaction уже проредил, что избыточно.

📋 context-mgmt скилл

Скилл ~/.config/opencode/skills/context-mgmt/SKILL.md содержит рекомендации по оптимизации контекста для free tier:

Когда сжимать:

  • ✅ После закрытого блока работы (задача завершена, исследование закончено)
  • ✅ При смене темы
  • ✅ Когда чувствуешь что контекст тяжёлый
  • ✅ После 20-30 сообщений без компрессии

Когда НЕ сжимать:

  • ❌ В середине активной задачи, если нужны точные ссылки на код/ошибки
  • ❌ Если следующий шаг зависит от деталей из истории

Дополнительные методы экономии контекста:

  • Использовать format="compact" в memory_recall
  • Делегировать исследовательские задачи сабагенту researcher (экономит ~50% контекста)
  • Делать задачи последовательно, не параллельно
  • Compress каждые 20-30 сообщений или при смене темы

⌨️ Команда /dcp-compress

Ручное сжатие контекста через чат-команду:

/dcp-compress

Принудительно запускает сжатие независимо от maxContextLimit. Полезно когда:

  • Чувствуется "тяжесть" в ответах модели
  • Перед сменой темы для "чистого листа"
  • После завершения крупной задачи

💡 Рекомендации по улучшению

  1. Авто-консолидация по расписанию: Настроить autoUpdate: true или добавить cron-триггер для периодической консолидации контекста в неактивные часы
  2. Динамическая настройка под модель: Сделать параметры DCP адаптивными — при смене модели с 200K на 1M менять maxContextLimit и minContextLimit
  3. Заполнить protectedTools: Указать инструменты, чей вывод нельзя удалять (например edit, write для active coding session)
  4. protectUserMessages: true — включить защиту сообщений пользователя от сжатия (сейчас выключено)
  5. Настроить preserve_recent_tokens — явно указать количество токенов для защиты (20000 для 200K модели)
  6. Интеграция с agentmemory: При DCP-сжатии автоматически сохранять session_summary в episodic память
