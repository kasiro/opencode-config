Multi-agent оркестрация

Сравнительный анализ фреймворков для multi-agent orchestration и применимость к J.A.R.V.I.S. Дата: июль 2026.

1. LangGraph

LangGraph (LangChain) — графовая оркестрация с максимальным контролем. Агенты представлены как узлы (nodes) графа, а переходы между ними — как рёбра (edges).

Ключевые возможности:

  • Stateful графы: каждый узел получает и модифицирует общее состояние (state)
  • Условные переходы: маршрутизация на основе содержимого state (if-else, switch)
  • Циклы и рекурсия: поддержка циклов в графе для итеративных процессов
  • Human-in-the-loop: возможность приостановить выполнение для ручного ввода
  • Checkpointing: сохранение состояния для отладки и восстановления
  • Streaming: пошаговый вывод результатов

Пример простого графа:

graph = StateGraph(AgentState)
graph.add_node("planner", plan_task)
graph.add_node("solver", solve_task)
graph.add_node("critic", critique_result)
graph.add_edge("planner", "solver")
graph.add_conditional_edges("solver", should_retry, {
    True: "critic",
    False: END
})
graph.add_edge("critic", "solver")  # loop back

Когда использовать: когда нужен максимальный контроль над потоком, сложная логика ветвления, отладка каждого шага, stateful взаимодействие между агентами.

Минусы: высокий порог входа, много boilerplate кода, сложно быстро прототипировать.

2. CrewAI

CrewAI — фреймворк для role-based команд агентов. Быстрый старт, декларативная конфигурация.

Концепции:

  • Agent: роль, цель, бэкстори (backstory), модель, allow_delegation
  • Task: описание, ожидаемый результат, ассигнованный агент
  • Crew: группа агентов + процесс (sequential/hierarchical/consensual)
  • Process: sequential — по цепочке, hierarchical — менеджер назначает
  • Tools: интеграции (поиск, API, файлы), наследуются от LangChain

Пример команды:

researcher = Agent(role="Исследователь", goal="Найти информацию", backstory="Эксперт по поиску")
writer = Agent(role="Писатель", goal="Написать пост", backstory="Креативный копирайтер")
crew = Crew(agents=[researcher, writer], tasks=[research_task, write_task], process=Process.sequential)
result = crew.kickoff()

Когда использовать: быстрый прототип, стандартные workflows (research → write → review), малые и средние проекты.

Минусы: ограниченный контроль, сложно кастомизировать логику маршрутизации, проблемы с масштабированием при 10+ агентах.

3. AutoGen / AG2 (Microsoft)

AutoGen (переименован в AG2 в 2025) — conversational group chat архитектура. Агенты общаются друг с другом как участники чата.

Ключевые особенности:

  • GroupChat: несколько агентов в одной комнате, сообщения видны всем
  • Round-robin: агенты выступают по очереди или по выбору спикера
  • Handoffs: явная передача управления («передаю эстафету Агенту Б»)
  • Nested Chats: чат внутри чата (подзадача выделяется в отдельный диалог)
  • Termination: условия завершения (по достижению цели, по лимиту сообщений)
  • Code Execution: встроенный sandbox для выполнения кода

Пример:

assistant = GPTAssistantAgent("assistant")
user_proxy = UserProxyAgent("user", code_execution_config={"work_dir": "coding"})
groupchat = GroupChat(agents=[assistant, user_proxy], messages=[], max_round=10)
manager = GroupChatManager(groupchat=groupchat)
await manager.a_initiate_chat("Напиши скрипт для парсинга CSV")

Когда использовать: задачи, требующие multi-turn диалога между агентами, code generation с execution, исследовательские задачи.

Минусы: overhead на коммуникацию, сложно отлаживать длинные对话, latency при большом числе агентов.

4. OpenAI Agents SDK

OpenAI Agents SDK — легковесный SDK от OpenAI для построения multi-agent систем. Explicit handoffs + guardrails.

Архитектура:

  • Agent: инструкции (system prompt), модели, tools, handoffs
  • Handoff: явная передача управления другому агенту через agent.transfer()
  • Guardrails: валидация входа/выхода агента (input guardrails, output guardrails)
  • Runner: исполняет агента до завершения или handoff
  • Tracing: встроенное логирование всех шагов

Пример:

triage_agent = Agent(
    name="Triage",
    instructions="Определи, к какому специалисту направить запрос",
    handoffs=[billing_agent, support_agent, sales_agent]
)
result = await Runner.run(triage_agent, "У меня проблема с оплатой")

Когда использовать: проекты на OpenAI, быстрая интеграция с GPT-4o, нужны guardrails из коробки.

Минусы: Vendor lock-in (OpenAI), не поддерживает другие LM провайдеры, меньше гибкости чем LangGraph.

5. Google ADK (Agent Development Kit)

Google ADK — фреймворк для иерархических multi-agent систем с поддержкой протокола A2A (Agent-to-Agent).

Ключевые концепции:

  • Hierarchical Agent Tree: родительский агент делегирует подзадачи дочерним агентам
  • A2A Protocol: открытый протокол для взаимодействия агентов (JSON-RPC, capabilities discovery)
  • Built-in Tools: search, code execution, data analysis, MCP integration
  • Multi-modal: текст, изображения, аудио, видео
  • Evaluation: встроенные метрики для оценки качества агентов

Когда использовать: enterprise с Google Cloud, сложные иерархические workflows, кросс-платформенная оркестрация через A2A.

Минусы: привязка к экосистеме Google, относительно новый, меньше сообщества.

8. Применимость к OpenCode

Текущая архитектура OpenCode использует agentmemory signals как примитив оркестрации: signal_send / signal_read для меж-агентской коммуникации.

Сравнение с фреймворками:

  • LangGraph: сигналы — аналог рёбер графа, но без централизованного state. Можно построить граф поверх signals + agentmemory_state.
  • CrewAI: роли в OpenCode — subagent_type. Handoffs — через signal_send(type=handoff). Ближе всего по духу.
  • AutoGen: group chat — через broadcast signal. Но нет round-robin и ротации спикера.
  • OpenAI SDK: explicit handoffs — эквивалент signal_send(type=handoff, to=agent_id).

Чего не хватает в OpenCode:

  1. Оркестратор: центральный компонент, который управляет очередью задач, маршрутизацией и мониторингом агентов
  2. Agent Handoffs: стандартизированный протокол передачи управления между агентами с контекстом
  3. Group Chat / Broadcast: механизм multi-agent дискуссии
  4. Global State: общее состояние, доступное всем агентам (shared context)

9. Рекомендации

  1. Добавить agent handoffs в OpenCode: стандартизировать протокол передачи управления между subagent'ами через signal_send(type="handoff", to=agent_id, context={...}). Принимающий агент получает контекст + точку входа.
  2. Оркестратор поверх signals: создать специального агента-оркестратора, который слушает все сигналы, управляет очередью и принимает решения о маршрутизации. Использовать agentmemory_frontier для выбора следующего действия.
  3. Shared State: добавить глобальное состояние (через agentmemory или отдельный MCP сервер), доступное всем агентам. Это позволит реализовать паттерн «blackboard architecture».
  4. Адаптер для популярных фреймворков: создать MCP-мост для LangGraph/CrewAI — чтобы можно было запустить граф из LangGraph внутри OpenCode через tool call.
