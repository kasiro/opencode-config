🔍 Обзор

2025–2026 стали годами «протокольной войны» в AI-агентах. Четыре ключевых протокола — MCP, A2A, ACP и ANP — сформировали экосистему, где каждый решает свою задачу. Аналогия из веба: HTTP (передача данных), WebSocket (реалтайм) и gRPC (высокая производительность) — не конкуренты, а взаимодополняющие технологии.

🟢 Google A2A (Agent-to-Agent Protocol)

Анонсирован Google Cloud Next '25 (апрель 2025). Открытый протокол для взаимодействия независимых AI-агентов, построенных на разных фреймворках и у разных вендоров.

Agent Card — обнаружение возможностей

Каждый агент публикует JSON-документ (Agent Card), описывающий:

  • Capabilities — что агент умеет (skills, endpoints)
  • Authentication — как авторизоваться (OAuth 2.0, OIDC)
  • Rate limits — ограничения запросов
  • Pricing model — стоимость использования
  • Agent URL — конечная точка для A2A запросов

Task Lifecycle

A2A определяет жизненный цикл задачи (Task) между агентами:

  submitted ──→ working ──→ completed
       │                    │
       └──→ failed ─────────┘ (с причинами ошибки)
         (retry возможен)
СтатусОписание
submittedЗадача отправлена агенту-исполнителю
workingАгент выполняет задачу (может отправлять промежуточные результаты)
completedЗадача выполнена успешно
failedЗадача завершилась ошибкой (с кодом и описанием)

SDKs

Google выпустил официальные SDK для:

  • Python — pip install google-a2a
  • JavaScript/TypeScript — npm install @google/a2a
  • Go — go get github.com/google/a2a
  • Java — Maven Central: com.google.a2a
  • .NET — NuGet: Google.A2A

🟣 IBM ACP (Agent Communication Protocol)

IBM представила ACP в 2025 как brokered-архитектуру для мультимодальной коммуникации агентов. Ключевое отличие от A2A — поддержка не только текста, но и аудио, видео, изображений.

Архитектура:

  • Broker (ACE): центральный диспетчер сообщений между агентами
  • Session awareness: поддержка длительных multi-turn сессий с сохранением состояния
  • REST-native: performative messaging layer с HTTP + async streaming
  • Observability: встроенный мониторинг и трейсинг сообщений

Разница с A2A: A2A — peer-to-peer (агенты общаются напрямую), ACP — brokered (через центральный брокер). ACP также поддерживает мультимодальные форматы (аудио- и видеопотоки между агентами).

🟡 ANP (Agent Network Protocol)

Децентрализованный P2P-протокол от open-source сообщества. Полностью without центрального сервера.

Ключевые особенности:

  • P2P архитектура: каждый агент — равноправный узел сети
  • DID Identity: децентрализованная идентификация через W3C DID
  • IPFS / DHT: распределённое хранение Agent Cards и состояния
  • WebRTC / direct TCP: прямой транспорт между узлами
  • IETF draft: документ draft-zyyhl-agent-networks-framework на рассмотрении

Когда использовать: Если нужна полная децентрализация, приватность и отсутствие единой точки отказа. Подходит для p2p-рынков агентов, edge-сценариев.

🔵 MCP — фундамент

Model Context Protocol (MCP) от Anthropic остаётся стандартом для подключения инструментов и данных к LLM. В контексте A2A, MCP — это «руки и глаза» агента, а A2A — «голос для общения с другими агентами».

Иерархия протоколов в multi-agent системе:

┌─────────────────────────────────────┐
│         A2A / ACP / ANP             │ ← Agent-to-Agent коммуникация
├─────────────────────────────────────┤
│              Agent                   │ ← Логика, планирование, принятие решений
├─────────────────────────────────────┤

├─────────────────────────────────────┤

└─────────────────────────────────────┘

🎯 Применимость к Jarvis

AgentMemory Signals — уже свой A2A

Jarvis использует agentmemory_memory_signal_send/read — это фактически собственный Agent-to-Agent протокол:

agentmemory signalA2A аналог
send(to="agent-id")A2A Task Submit
read()A2A Task Get / Poll
type="request|response|handoff"A2A Message Types
replyToA2A Thread / Conversation ID
broadcastA2A Agent Discovery

Рекомендации

  1. Agent Card для Jarvis: Создать JSON-документ, описывающий возможности Jarvis (skills, MCP серверы, permissions) — для обнаружения другими агентами
  2. Multi-protocol поддержка: Реализовать MCP для инструментов + агентmemory signals для внутренней A2A + факультативный A2A SDK для внешних агентов
  3. Signal → A2A bridge: Мост между agentmemory signals и A2A протоколом для взаимодействия с внешними агентами от Google, AWS и др.
  4. A2A Task Lifecycle: Использовать lifecycle (submitted→working→completed→failed) для трекинга задач между агентами Jarvis
  5. Hybrid discovery: Agent Card для публичных возможностей + agentmemory для внутреннего обнаружения агентов
