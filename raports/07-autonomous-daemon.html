Архитектура EventBus (референс из Jarvis)

Файл: ~/.config/opencode/skills/pc-control/api/event_bus.py

# Ключевые методы EventBus:
# subscribe(event_type, callback) — подписка на событие
# unsubscribe(event_type, callback) — отписка
# publish(event_type, data) — публикация события (асинхронно, всем подписчикам)
# set_state(key, value) — установка состояния (авто-публикация state:{key})
# get_state(key) — чтение состояния
# get_all_state() — полный слепок состояний

# Типы событий в pc-control:
# - state:mode_changed — режим изменился
# - state:vpn_connected — VPN подключён
# - command:executed — команда выполнена
# - state_changed — любое изменение состояния

Недостатки текущей реализации:

  • Локальная (только в рамках одного процесса)
  • Нет персистентности (при перезапуске состояния теряются)
  • Нет межпроцессного взаимодействия
  • Нет MCP интерфейса

Предлагаемый MCP EventBus

MCP сервер, который предоставляет EventBus через стандартный протокол OpenCode:

{
  "mcpServers": {
    "eventbus": {
      "command": "python3",
      "args": ["~/.config/opencode/mcp/eventbus_server.py"]
    }
  }
}

# Инструменты MCP EventBus:
# 
# publish(event_type: str, data: dict) → void
#   Отправить событие всем подписчикам
#
# subscribe(event_type: str, callback_tool: str) → subscription_id
#   Подписаться на событие (указать tool для вызова при событии)
#
# unsubscribe(subscription_id: str) → void  
#   Отписаться от события
#
# state_get(key: str) → any
#   Получить значение состояния
#
# state_set(key: str, value: any) → void
#   Установить значение состояния (публикует событие state:{key})
#
# schedule(cron_expr: str, action: str) → schedule_id
#   Запланировать периодическое действие
#
# signal_send(target: str, type: str, data: dict) → void
#   Отправить сигнал конкретному агенту/компоненту

Systemd user unit

# ~/.config/systemd/user/opencode-daemon.service
[Unit]
Description=OpenCode Daemon — 24/7 AI Assistant
After=network.target

[Service]
Type=simple
ExecStart=/usr/bin/bunx opencode daemon
Restart=on-failure
RestartSec=5
Environment=OPENCODE_DAEMON=1

# Лимиты
LimitNOFILE=4096
MemoryMax=2G

[Install]
WantedBy=default.target

# Установка и запуск:
# systemctl --user daemon-reload
# systemctl --user enable --now opencode-daemon.service
# journalctl --user -u opencode-daemon -f

Пошаговый план внедрения (3-5 дней)

ДеньЧто делаемРезультат
День 1 Создать MCP EventBus сервер. Перенести EventBus из pc-control в отдельный MCP сервер. Добавить персистентность через SQLite. EventBus работает как MCP сервер. Подписка/публикация через инструменты.
День 2 Создать systemd user unit. HTTP/WebSocket API сервер (FastAPI). Эндпоинты: POST /publish, POST /execute, GET /state. OpenCode запускается как демон. Доступен по HTTP.
День 3 Планировщик (cron внутри EventBus). File Watcher (watchdog → publish событий). Фоновые задачи по расписанию. Авто-реакция на изменения файлов.
День 4 Webhook приёмник. Интеграция с GitHub (push → авто-действие), Telegram ботом. OpenCode реагирует на внешние события.
День 5 Стабильность: авто-рестарт, healthcheck, мониторинг, Graceful shutdown. Документация. 24/7 работа без присмотра.

┌──────────────┐ publish("user:said", {"text": "..."}) ┌──────────────┐ │ STT сервер │─────────────────────────────────────────────→│ │ │ (голос) │ │ EventBus │ └──────────────┘ │ (MCP) │ │ │ ┌──────────────┐ subscribe("state:mode", callback) │ ┌─────────┐ │ │ pc-control │←────────────────────────────────────────────│ │ SQLite │ │ │ MCP │ │ │ (state) │ │ └──────────────┘ │ └─────────┘ │ └──────┬───────┘ ┌──────────────┐ schedule("0 */1 * * *", "consolidate") │ │ Scheduler │───────────────────────────────────────────────────→│ └──────────────┘ │ ▼ ┌──────────────────┐ │ OpenCode Core │ │ (LLM + Tools) │ └──────────────────┘

Резюме: Самое слабое место OpenCode — отсутствие фонового режима. Без демона это инструмент для сессионной работы. EventBus из pc-control — готовый фундамент, который нужно вынести в MCP сервер и расширить. 5 дней до 24/7 режима.
