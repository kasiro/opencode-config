⚔️ OpenCode vs Jarvis: Сравнительный анализ

OpenCode Jarvis сравнение

🎯 Обзор

Сравнение двух экосистем — OpenCode (фреймворк для AI-агентов) и Jarvis (старая система, работающая через HTTP API и shell-скрипты). Обе системы выполняют роль голосового ассистента, но имеют принципиально разную архитектуру.

Текущий статус: OpenCode уже покрывает 60-70% функциональности Jarvis. Критические пробелы — голосовой ввод/вывод и демонизация.

🔬 Детальный разбор

✅ Что OpenCode делает лучше

🧠 Память (4-tier vs .state.json)

OpenCode использует agentmemory с 4 уровнями консолидации: Working → Episodic → Semantic → Procedural. Frozen Snapshot Pattern предотвращает инвалидацию KV-кэша. 53 инструмента для работы с памятью — граф, рефлексия, уроки, диагностика. Jarvis использует плоский .state.json без консолидации.

🤖 Агенты (5 vs 1)

OpenCode поддерживает 5 суб-агентов с разными permission и инструментами: executor (код), researcher (исследования), sysadmin (система), general (гибрид), explore (быстрый просмотр). Jarvis — один монолитный агент, где всё смешано.

🏗️ Архитектура (Plugin/MCP vs монолит)

OpenCode построен на plugin-системе + 10 MCP серверах. Каждый компонент заменяемый. Jarvis — Python-монолит с HTTP API, сложно расширять.

🔗 Интеграции (SearXNG/Context7/DeepWiki vs HTTP)

OpenCode подключает внешние сервисы через MCP: SearXNG (поиск), Context7 (документация), DeepWiki (GitHub репозитории), Crawl4AI (парсинг), YouTube Transcript, Exa. Jarvis использует прямые HTTP запросы.

✅ Что Jarvis делает лучше

🎤 Голосовой ввод (Vosk)

Jarvis имеет полноценный STT на базе Vosk — оффлайн, без интернета, на русском языке. OpenCode полностью текстовый — голосовой ввод отсутствует.

🔊 TTS (Piper/Espeak)

Jarvis синтезирует речь через Piper TTS (нейросеть, качественный голос) и Espeak (fallback, быстрый). OpenCode не озвучивает ответы.

🗣️ Wake Word (RustPotter)

Jarvis постоянно слушает эфир и просыпается по слову "Jarvis". OpenCode не поддерживает wake-word — нужно вводить команды вручную.

📡 EventBus

Jarvis имеет полноценную шину событий с триггерами: wake_word_detected → stt_ready → nlu_process → tts_done. OpenCode имеет только сигналы между агентами (signal_send/signal_read) без централизованного EventBus.

🎯 Вывод: OpenCode — 60-70% Jarvis

OpenCode уже покрывает 60-70% функциональности Jarvis и превосходит его в ключевых архитектурных аспектах: память, агенты, модульность и интеграции. Однако для полноценной замены Jarvis как голосового ассистента не хватает критических компонентов.

📋 Критические пробелы для закрытия

ПробелПриоритетПредлагаемое решение
STT Высокий Подключить Vosk через MCP сервер или плагин. Vosk работает локально, без API ключей.
TTS Высокий Подключить Piper TTS через MCP. Качественный русский голос. Открытая лицензия.
Демонизация Средний OpenCode уже работает как CLI, но для демонизации нужен systemd сервис. opencode daemon или systemd user service.
Event-driven Средний Добавить EventBus MCP сервер для подписки на события. Связать wake_word → STT → NLU → TTS.
Внешний API Средний HTTP API для интеграции с внешними системами. OpenCode пока только CLI.
