Memory системы для LLM агентов

Сравнительный анализ систем долговременной памяти для AI-агентов и применимость к OpenCode. Дата: июль 2026.

1. Mem0 — семантический слой памяти

Mem0 (48k+ ★) — ведущая open-source система памяти для LLM-агентов. Предоставляет семантический слой памяти с автоматическим извлечением, обновлением и поиском.

ПараметрЗначение
Звёзд GitHub48k+
АрхитектураSemantic memory layer поверх vector DB (Qdrant, Chroma, Pinecone)
LoCoMo Score92.5 (benchmark долгосрочной памяти)
LongMemEval94.4 (benchmark извлечения фактов)
Ключевая инновацияАвтономное обновление памяти: старые факты перезаписываются новыми
ЯзыкиPython, Node.js, REST API
ЛицензияApache 2.0

API:

from mem0 import Memory

m = Memory()
result = m.add("My name is John", user_id="john")
# → {"id": "m1", "content": "My name is John", "metadata": {...}}

# Поиск по семантике
results = m.search("What is my name?", user_id="john")
# → [{"content": "My name is John", "score": 0.92}]

Для чего: долговременное запоминание пользовательских предпочтений, фактов из диалога, кросс-сессионная идентичность.

2. Multi-signal Retrieval

Современный тренд — комбинирование нескольких сигналов для поиска релевантных воспоминаний:

СигналОписаниеПример
SemanticВекторное сходство (embedding cosine similarity)Поиск по смыслу: «как исправить баг с авторизацией»
KeywordBM25 / TF-IDF точное совпадение терминовПоиск по точному термину: «JWT token expired»
EntityИзвлечение именованных сущностей (NER)Поиск по entity: конкретный файл, функция, класс
TemporalВременная релевантность (recency)То, что было недавно — выше весом
GraphСвязи между фактами через knowledge graphФакт связан с другими через отношение

Фьюжн-результат — weighted комбинация всех сигналов с динамическими весами. Рекомендуемый подход для production.

3. Knowledge Graph Memory

Хранение фактов в виде графа знаний: узлы — сущности, рёбра — отношения. Поддерживает temporal validity (дата актуальности факта).

Преимущества перед Vector RAG:

  • Multi-hop reasoning: «Кто написал код, который вызвал баг в модуле X?» → traverse по графу (Person → wrote → Code → caused → Bug)
  • Отношения: граф хранит не просто «что», а «как связано»
  • Temporal queries: «Какие баги были исправлены на прошлой неделе?»
  • Консистентность: граф обеспечивает целостность (один факт — один узел)

Формат хранения: (subject, predicate, object, timestamp, confidence)

("Jarvis", "исправил", "баг#42", "2026-06-30", 0.95)
("баг#42", "связан_с", "модуль_авторизации", "2026-06-30", 0.9)
("модуль_авторизации", "написан_на", "TypeScript", "2026-01-01", 1.0)

7. Архитектура agentmemory (OpenCode)

Текущая реализация в OpenCode — 4-tier иерархия:

┌─────────────────────────────────────────────────┐
│                  Procedural Tier                  │
│  (автоматические навыки, заученные паттерны)      │
├─────────────────────────────────────────────────┤
│                  Semantic Tier                    │
│  (обобщённые концепции, долгосрочные факты)       │
├─────────────────────────────────────────────────┤
│                  Episodic Tier                    │
│  (сессии, конкретные события, наблюдения)         │
├─────────────────────────────────────────────────┤
│                  Working Tier                     │
│  (текущий контекст, активные цели)               │
└─────────────────────────────────────────────────┘

Консолидация происходит автоматически: working → episodic → semantic → procedural. Система основана на векторном поиске с confidence scoring.

8. Паттерны памяти

Гибрид Vector + Knowledge Graph

Рекомендуемый паттерн для production:

  1. Vector store для семантического поиска по тексту (быстро, неструктурированно)
  2. Knowledge Graph для структурированных фактов и отношений (точно, связно)
  3. Fusion retriever: объединяет результаты обоих, ранжирует по confidence

Temporal Facts

Каждый факт содержит временную метку и может содержать expiry (срок годности):

  • {"fact": "User's name is John", "timestamp": "2026-06-30", "expiry": null} — бессрочно
  • {"fact": "API key: sk-...", "timestamp": "2026-06-30", "expiry": "2026-07-30"} — временный
  • {"fact": "Project is in development", "timestamp": "2026-06-30", "expiry": "rolling"} — с автоматическим обновлением

Single-pass Extraction

Извлечение фактов из одного прохода (без повторной обработки):

# Один вызов LLM: "Извлеки факты из диалога"
extracted = llm.extract_facts(dialogue)
# → [("subject", "predicate", "object", confidence)]
memory.store(extracted)

Consolidation Pipeline

Периодическая консолидация: объединение дублирующихся фактов, удаление устаревших, повышение confidence подтверждённых:

  1. Сканирование фактов с low confidence (0.3-0.5)
  2. Проверка: есть ли подтверждение в других фактах?
  3. Если да — повысить confidence; если нет — удалить
  4. Объединение дубликатов (same subject + predicate → merge objects)
  5. Применение temporal decay к старым неподтверждённым фактам

10. Рекомендации

  1. Multi-signal retrieval: расширить текущий semantic-only поиск в agentmemory до multi-signal (semantic + keyword + entity + temporal). Использовать weighted fusion.
  2. Temporal Knowledge Graph: добавить knowledge graph слой поверх agentmemory mesh для хранения структурированных фактов с временными метками и expiry.
  3. Cross-session identity: внедрить Mem0-style автономное обновление памяти при пересечении сессий. Если агент встречает факт, противоречащий сохранённому — разрешить конфликт через confidence score.
  4. Consolidation pipeline: улучшить текущую 4-tier консолидацию: добавить дедупликацию, temporal decay, automated verification через cross-check с knowledge graph.
  5. Mem0 bridge: создать MCP-сервер-мост между agentmemory и Mem0 — использовать agentmemory для 4-tier внутренней памяти, Mem0 для long-term semantic памяти о пользователе.
