🔍 Обзор

Современные AI-агенты всё чаще работают не в режиме «запрос→ответ», а как фоновые процессы, запускаемые по расписанию (cron, Temporal Schedules) или по событиям (webhook, file system watch, signal). 2025–2026 принесли зрелые платформы для durable execution — Temporal стал стандартом для agentic workflow с гарантиями выполнения, а OpenClaw показал zero-polling event-driven архитектуру.

По данным AgentCenter 2026, организации в среднем используют 50–200+ агентов, из которых 30–40% работают в фоновом scheduled/event-driven режиме.

⏳ Temporal — Durable Execution Engine

Temporal — open-source платформа durable execution, ставшая стандартом для надёжных AI-воркфлоу. Позволяет запускать долгоживущие процессы, которые автоматически восстанавливаются после падений, перезагрузок и сетевых сбоев.

Ключевые концепции

КонцепцияОписаниеДля AI-агентов

ActivityАтомарный шаг workflow (вызов API, tool use, расчёт)Один tool call или действие агента

ScheduleSpec

Temporal ScheduleSpec — CRON-подобное расписание с гарантиями выполнения:

  • Calendar-based: */5 * * * * (каждые 5 минут)
  • Interval-based: каждые N секунд/минут/часов
  • Structured calendar: день недели + месяц + год
  • Time zone aware: поддержка часовых поясов
  • Backfill: запуск пропущенных выполнений
  • Pause/Resume: приостановка без потери конфигурации
  • Last completion check: предотвращение дублирования

Heartbeat мониторинг

Temporal предоставляет механизм Heartbeat для контроля, что Activity (или агент) жив:

  async def agent_heartbeat_activity():
      while not completed:
          result = await agent_step()
          # Сообщаем Temporal: "я жив, прогресс: 45%"
          activity.heartbeat(result)
          await asyncio.sleep(5)

Если Heartbeat не поступает N минут → Activity помечается как stalled → Temporal запускает retry или fallback.

AI-агенты на Temporal — пример

Из Temporal blog (сентябрь 2025): 24/7 crypto trading system с агентами:

  • Scheduled agent: запускается каждые 15 минут для анализа рынка
  • Signal-driven agent: реагирует на ценовые события (price alert)
  • MCP integration: Temporal Workflow вызывает MCP-инструменты через Activities
  • Durable tools: каждый tool call — отдельная Activity с retry

🔧 OpenClaw Hooks — Zero-Polling Event-Driven

OpenClaw (open-source personal AI assistant) использует Hooks — event-driven архитектуру без опроса (zero-polling).

Преимущества:

  • Zero CPU/time в ожидании — нет polling
  • Мгновенная реакция на события
  • 5700+ community-built skills через ClawHub

🔄 Гибрид: Scheduled + Event-Driven

Самый мощный паттерн — комбинация расписания и событий в одном workflow:

  ┌──────────────────────────────────────────────┐
  │           Temporal Workflow                   │
  │                                              │
  │  ⏰ Scheduled: каждые 15 минут → Check       │
  │     └─→ Activity: проверить почту            │
  │     └─→ Если есть важное → Signal → Agent    │
  │                                              │
  │  📩 Signal-driven: webhook → New Issue       │
  │     └─→ Agent: проанализировать issue        │
  │     └─→ Создать PR с фиксом                  │
  │     └─→ Проверить CI/CD                      │
  │                                              │
  │  📊 Query: статус задач агента               │
  │  ❤️ Heartbeat: каждые 30 сек "я жив"         │
  └──────────────────────────────────────────────┘

Этот паттерн позволяет агенту быть проактивным (проверять почту самому) и реактивным (мгновенно реагировать на webhook), сохраняя полное состояние и контекст.

🎯 Применимость к Jarvis

Jarvis Scheduler

Текущие возможности Jarvis для фоновых задач:

  • systemd timer — уже используется для agentmemory.service, pc-control скриптов
  • agentmemory signals — event-driven коммуникация между агентами
  • Скиллы: pc-control может быть расширен scheduled-скиллами

Рекомендации

  1. Temporal для durable execution: Внедрить Temporal для сложных долгоживущих задач — фоновой обработки, multi-step автоматизации, гарантированного выполнения
  2. Signal-based triggers: Расширить agentmemory signals до полноценной event-driven архитектуры — file watchers, почтовые триггеры, webhook endpoint
  3. Proactive skills: Скиллы, которые запускаются по расписанию (каждое утро в 8:00), а не только по запросу
  4. Heartbeat мониторинг: Для фоновых агентов Jarvis — heartbeat проверка, что агент жив и выполняет задачу
  5. Scheduled + event-driven гибрид: Например: cron-проверка почты каждые 15 минут + мгновенная реакция на webhook для срочных задач
  6. Self-healing: Автоматический перезапуск упавших фоновых задач через systemd timer или Temporal
