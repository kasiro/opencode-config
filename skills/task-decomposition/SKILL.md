# Task Decomposition — Справочник по декомпозиции задач

## Для чего нужен этот скилл

Этот скилл — **справочный материал** для CYCLE 1.5 (Task Intake Protocol). Он содержит:
- Шаблоны декомпозиции для типовых задач
- Критерии качества плана
- Типичные ошибки и как их избежать
- Примеры хорошей и плохой декомпозиции

Используй его когда:
- Задача complex (6+ шагов) — нужна качественная декомпозиция
- Задача новая / незнакомая — нужны шаблоны
- При проверке плана — свериться с чек-листом

## Шаблоны декомпозиции

### 1. Research задача (изучить, найти, сравнить)

```
Шаг 1: researcher — поиск источников (searxng / context7)
  ↓
Шаг 2: researcher — детальный разбор топ-3 источников (web_url_read)
  ↓
Шаг 3: jarvis — синтез результатов в структурированный ответ
         и проверка полноты по вопросам сэра
```

**Критерии успеха:** минимум 3 источника, структурированный вывод (таблица/список)

### 2. Code задача (написать, отрефакторить)

```
Шаг 1: explore — изучить текущую структуру проекта
  ↓
Шаг 2: researcher — найти best practices / библиотеки (если нужно)
  ↓
Шаг 3: executor — написать код + проверить build/test + curl / run
```

**Критерии успеха:** build проходит, тесты зелёные, API отвечает

### 3. Hybrid задача (исследовать + применить)

```
Шаг 1: researcher — изучить best practices / документацию
  ↓
Шаг 2: general — применить findings к коду + проверить build/test
  ↓
Шаг 3: jarvis — итоговая верификация + измерить разницу
```

**Критерии успеха:** улучшение измеримо, код соответствует best practices

### 4. Install / Настройка

```
Шаг 1: researcher — найти способ установки (docs/пакет)
  ↓
Шаг 2: executor — установить/настроить + проверить health/status
  ↓
Шаг 3: jarvis — записать урок (что сработало)
```

### 5. Debug задача (найти и починить баг)

```
Шаг 1: jarvis — воспроизвести баг (анализ вывода сэра / запуск)
  ↓
Шаг 2: explore — grep/rg по коду для поиска возможной причины
  ↓
Шаг 3: researcher — поиск похожих багов / issues
  ↓
Шаг 4: executor — применить фикс + проверить тесты
  ↓
Шаг 5: jarvis — подтверждение что баг не воспроизводится
```

## Чек-лист качества плана

Перед утверждением плана проверь:

- [ ] Каждый шаг имеет одного ответственного агента
- [ ] Зависимости между шагами корректны (DAG — нет циклов)
- [ ] Для каждого шага определён метод верификации
- [ ] Максимальная глубина зависимостей < 5 (иначе слишком длинная цепочка)
- [ ] Общее количество шагов < 15 (лимит контекста)
- [ ] Нет шагов типа "разберись" — каждый шаг конкретен
- [ ] Для research шагов указано что искать
- [ ] Для code шагов указан конкретный файл/функция

## Типичные ошибки

| Ошибка | Пример | Как избежать |
|--------|--------|-------------|
| Слишком крупные шаги | «Написать приложение» | Разбить на: scaffold → routes → бизнес-логика → тесты |
| Пропущена верификация | Нет шага проверки | Каждый шаг должен иметь критерии проверки |
| Неявные зависимости | Шаг 3 требует результат шага 1, но это не указано | Явно прописать depends_on |
| Лишние шаги | Исследовать то что уже известно | Проверить lesson_recall / memory_recall |
| Неверный выбор агента | researcher для рефакторинга | researcher → только поиск, executor → код |
| Слишком много параллельных | 4 агента одновременно | Max 2 background задачи параллельно |

## Адаптация под сложность

| Сложность | Макс шагов | Глубина зависимостей | Confirmation Loop |
|-----------|-----------|---------------------|-------------------|
| simple (1-2 шага) | 2 | 1 | Не нужен |
| medium (3-5 шагов) | 5 | 2 | Краткое подтверждение |
| complex (6+ шагов) | 12 | 3 | Полный confirm + чек-лист |

## Пример хорошей декомпозиции

**Задача:** «Добавить MCP сервер для работы с файловой системой»

**План:**
```
Шаг 1 [research → researcher]: 
  Найти npm пакет @modelcontextprotocol/server-filesystem
  Deps: []
  Verify: найден пакет, версия, docs

Шаг 2 [code → executor]:
  Установить пакет, добавить в opencode.json mcpServers,
  проверить что сервер запускается (curl localhost:port)
  Deps: [step_1]
  Verify: opencode.json валиден, пакет установлен, ответ 200

Шаг 3 [save → jarvis]:
  Записать урок: какие настройки сработали
  Deps: [step_2]
  Verify: lesson_save выполнена
```
